# Firmata Protocol Support

Ardulink-2 version 2.2.0 introduces experimental support for the [Firmata protocol](https://github.com/firmata/protocol) — a well-established standard for communicating with microcontrollers from host software.

## What Is Firmata?

Firmata is a generic protocol for communicating with microcontrollers from a host computer. It is widely supported and allows:

- Digital pin read/write
- Analog pin read/write
- PWM output
- Servo control
- I2C communication
- SPI communication
- Pin mode configuration

The [StandardFirmata](https://github.com/firmata/arduino) sketch is the reference implementation for Arduino boards.

## Enabling Firmata in Ardulink-2

Firmata support is currently a preview feature. Enable it by setting a system property before creating a link:

```java
import org.ardulink.core.Link;
import org.ardulink.core.pin.Pin;
import org.ardulink.core.convenience.Links;

public class FirmataExample {
    public static void main(String[] args) throws Exception {
        // Enable Firmata protocol
        System.setProperty("protocol.firmata.enabled", "true");

        try (Link link = Links.getDefault()) {
            link.switchDigitalPin(Pin.digitalPin(13), true);
        }
    }
}
```

Or set it on the command line:

```bash
java -Dprotocol.firmata.enabled=true -jar your-app.jar
```

## Arduino Firmware for Firmata

Unlike the custom Ardulink firmware, Firmata uses the standard [StandardFirmata](https://github.com/firmata/arduino) sketch:

### Using Arduino IDE

1. Open Arduino IDE
2. Go to **File > Examples > Firmata > StandardFirmata**
3. Select your board and port
4. Click **Upload**

### Using WebSerial

You can also upload StandardFirmata via the WebSerial Flasher or other browser-based tools.

## Maven Dependency

```xml
<dependency>
    <groupId>org.ardulink</groupId>
    <artifactId>ardulink-core-firmata-proto</artifactId>
    <version>2.2.0</version>
</dependency>
```

## Current Limitations

{: .warning }
Firmata support is experimental and subject to change. The following features are not yet fully implemented:

- **Ad-hoc querying** — The sketch cannot proactively send values without being queried (needed for features like REST API value retrieval)
- **Startup data** — Pin states are not automatically sent at connection time
- **Version negotiation** — No version information exchange between Java and firmware

These limitations are tracked as open items in the [Ardulink-2 issue tracker](https://github.com/Ardulink/Ardulink-2/issues/5).

## When to Use Firmata vs Ardulink Firmware

| Aspect | Ardulink Firmware | Firmata |
|:-------|:-----------------|:--------|
| Protocol | Ardulink custom | Standard Firmata |
| Custom messages | Yes | Limited |
| Tone support | Yes | Via Firmata extensions |
| Ecosystem | Ardulink-specific | Widely supported |
| Library support | Ardulink-2 only | Many languages |
| Active development | Yes | Yes (different project) |

**Use Ardulink firmware** when you need full feature support and custom protocols.
**Use Firmata** when you want compatibility with other Firmata-based tools or when portability across languages matters.

## Protocol Specification

The Firmata protocol is documented at [github.com/firmata/protocol](https://github.com/firmata/protocol). Key message types:

| Message | Direction | Description |
|:--------|:----------|:------------|
| `ANALOG_MESSAGE` | Both | Analog pin value (0-127 per byte) |
| `DIGITAL_MESSAGE` | Both | Digital port state |
| `SET_PIN_MODE` | Host → Arduino | Configure pin mode |
| `REPORT_ANALOG` | Host → Arduino | Enable/disable analog reporting |
| `REPORT_DIGITAL` | Host → Arduino | Enable/disable digital reporting |
| `START_SYSEX` / `END_SYSEX` | Both | Extended message boundary |
